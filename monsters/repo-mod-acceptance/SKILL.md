# Игровая приёмка монстра

1. Зафиксируй требования, исходную версию и кандидат. Укажи SHA-256 пакета и DLL, игру, зависимости, режим и конфигурацию прогона. Если изменилась любая значимая часть проверяемого входа, повтори затронутый сценарий.
2. Выбери уровень проверки по механике. Используй чистые C#-тесты для правил и переходов, Unity Edit/Play Mode для prefab, привязок и физики, нативный запуск для спавна, уровня, урона и полного цикла. Для кооператива используй хоста и реального клиента. Состояние оригинальных сохранений проверяй до и после игрового запуска.
3. Повтори одинаковые стимулы на базе и кандидате. Записывай фактически загруженные комнаты и статическую геометрию, старт, путь, реальные вводы, время, сработавшие механизмы и причины выхода. Для обычного прогона оставляй поведение монстра его штатному ИИ. Пробы с отключённым драйвером или подставленной геометрией маркируй как диагностические.
4. Сохраняй исход каждой проверки по наблюдениям. Успех требует полного результата. Если стимул отсутствовал или проверяемый код не сработал, прогон требует повтора. Сбой после успешного контакта фиксируй как отдельный сбой. Записывай, где остались лестницы, атаки, совместимость, нагрузка или клиентские проверки.
5. Передай владельцу точный кандидат и короткий маршрут приёмки. Записывай решение владельца для конкретной версии, когда оно получено. После выполнения применимых критериев закрой или архивируй именно эту версию по правилам проекта.

Используй [матрицу проверок и пример записи прогона](references/verification-matrix.md), чтобы выбрать относящиеся к поведению проверки и сохранить достаточные данные для повтора.
