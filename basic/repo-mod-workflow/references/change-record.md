# Запись изменения

Используй существующие имена и схему проекта. При OpenSpec обычно достаточно следующего набора по мере выполнения этапов.

| Артефакт | Что записать |
| --- | --- |
| `proposal.md`, `context.md` | Цель игрока, платформа, проверенные версии и известные ограничения |
| `design.md`, `specs/` | Согласованная механика, дизайн и требования с наблюдаемыми сценариями |
| `verification.json` | Версия условий, идентификаторы проверок, команды или ручные шаги, ожидаемые результаты |
| `tasks.md`, `state.json` | Входы и зависимости задач, текущий этап, решения, блокер, следующее действие |
| `implementation.md`, `evidence.json` | Что изменилось, какой кандидат запускался, фактические результаты и ссылки на логи |
| `acceptance.md`, `closure.md` | Пройденные критерии, исключения и решение о закрытии для конкретной версии |

Пример передачи для навигации: «База и кандидат собраны для одной версии игры. На кандидате пройдена короткая рама Manor. Wizard-эпизод остановился на опоре. Следующий шаг — воспроизвести тот же Wizard-эпизод с записью фактической позиции корпуса и состояния опор. Длинную погоню проверяем после короткой пары. Точная DLL и конфигурация теста лежат в записи прогона».

В разработке Обручника исторические записи о текущих запусках оставались в старых разделах. При передаче помог отдельный блок с текущим коммитом, хешем, открытым сценарием и условиями повторного запуска. Сохраняй предыдущие результаты с их версиями и ясно указывай актуальную запись.
