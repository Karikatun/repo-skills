# Изоляция игровых тестов R.E.P.O.

1. Определи фактические места записи игры, Unity и загружаемых плагинов. Проверь `Application.persistentDataPath`, `PlayerPrefs`, ES3, файлы REPOLib и другие данные активного набора модов. Путь отдельного профиля Thunderstore определяет загрузку плагинов, а хранилище пользовательских данных может остаться общим.
2. Собери выделенную копию или профиль с минимальными зависимостями и отдельным корнем данных. Если нужна переадресация, проверяй её до старта плагинов в тестовом процессе. Зафиксируй, откуда выполняется запуск и какие библиотеки реально загрузились.
3. До первого разрешённого игрового запуска инвентаризируй защищённые файлы и нужные ключи настроек. Сохрани резервную копию и SHA-256. Храни исходные сохранения вне папки, куда пишет тест.
4. Сделай короткий smoke-тест, который проходит реальный путь загрузки и записи, затем чистый выход. Проверь наличие ожидаемых записей в изолированном хранилище, снимок оригиналов до/после и отсутствие новых записей в защищённых каталогах. Если хранилища пересеклись, останови следующие прогоны и установи записавший компонент. Восстановление пользовательских сохранений выполняй лишь при разрешении на эту операцию.
5. Повтори smoke-тест при смене версии игры, стартового профиля или механизма изоляции. Для очередного игрового кандидата записывай результат проверки сохранений вместе с исходом сценария.

Разбор утечки через REPOLib и наблюдаемые признаки исправления находятся в [кейсе Boobees Valuables](references/boobees-save-isolation.md).
