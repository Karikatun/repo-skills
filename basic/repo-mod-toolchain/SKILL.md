# Инструменты разработки R.E.P.O.

1. Найди установленную игру через Steam и выбранный профиль менеджера модов. Запиши версию игры и Steam build, фактическую версию Unity Player, версии DLL BepInEx, REPOLib и других обязательных зависимостей. Проверь дубликаты, если комплект файлов расходится с манифестом профиля.
2. Проверь Unity Editor и `ProjectVersion.txt`, `Packages/manifest.json` и `packages-lock.json`. Версию редактора выбирай по требованиям SDK и совместимости импорта/AssetBundle. Для C# проверь `dotnet --list-sdks`, настройки проекта и целевую платформу. `netstandard2.1` использовался для Обручника, а совместимость нового проекта определяется локальным API и загрузчиком.
3. Сверь нужные типы, поля и сигнатуры с установленными managed-сборками и исходниками REPOLib подходящей версии. Используй локальные ссылки или подготовленный SDK. Проверь, что игровые и сторонние DLL не копируются в готовый ZIP.
4. Выполни минимальную проверку нужной операции. Для Unity это маленький импорт или сборка в проекте с логом и выходным файлом, для Blender — headless-вызов со скриптом и проверяемым экспортом, для FFmpeg — вывод файла и проверка параметров через `ffprobe`. Установленный Unity Editor проверяй фактическим запуском: наличие executable не проверяет лицензию и компиляцию.
5. Если сборка или запуск блокируется, сохрани первую причинную ошибку, фактическую команду, версии и последний известный рабочий вариант. Меняй одну зависимость или настройку за цикл и повторяй исходную проверку.

На Windows можно брать путь из Steam library manifest, версию Unity из заголовка `Player.log`, а версии загрузчика и загруженных плагинов из BepInEx LogOutput. Данные `manifest.json` сравнивай с тем, что фактически загрузилось.

Для API и совместимости сверяй [репозиторий REPOLib](https://github.com/ZehsTeam/REPOLib), [пакеты REPOLib](https://thunderstore.io/c/repo/p/Zehs/REPOLib/) и [исходники BepInEx](https://github.com/BepInEx/BepInEx).
