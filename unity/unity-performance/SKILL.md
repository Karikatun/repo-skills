# Поиск узкого места в Unity

1. Выбери воспроизводимый эпизод и метрику под жалобу. Для рывка сохрани время проблемных кадров, для роста памяти — состояние до и после повторяемого цикла. Зафиксируй устройство, версию сборки, разрешение, настройки качества и условия прогрева.
2. Запиши исходный прогон. Для вывода о производительности игрока используй сопоставимый Player на целевом устройстве. Захват в Editor подходит для локализации причины. Запиши, где именно сделан замер.
3. Выбери инструмент по наблюдению. Для долгого кадра начни с Timeline в Unity Profiler и раздели работу CPU, GPU и ожидание. Для лишних проходов отрисовки найди конкретное событие во Frame Debugger. Для частых сборок мусора ищи источник GC.Alloc. Для удерживаемых объектов сравни снимки Memory Profiler после одинакового цикла.
4. Измени одну подтверждённую причину и повтори тот же эпизод с тем же способом записи. Сравни время кадров, пики или объём удерживаемой памяти и проверь, сохранилось ли поведение сцены. При заметном разбросе повтори замер. Запиши условия, значения до и после и ссылку на захват.

## Справочники по задаче

- Подключить Profiler к Player, поставить маркер, разобрать вызовы отрисовки или сравнить группы кадров — [профилировщик и захват](references/profiler-guide.md).
- Объяснить выделения, удержание ресурсов и последствия пулов — [память](references/memory-optimization.md).
- Подобрать эксперимент после локализации проблемы в физике, рендеринге, IL2CPP или загрузке сцены — [примеры оптимизаций](references/optimization-patterns.md).
